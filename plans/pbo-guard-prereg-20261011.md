# 预注册 · 判据链 #44 · **M4（PBO 门）加固 + 读数前提显式化**（2026-10-11 冻结）

> **触发**：#42 补算 M4 时发现 `PBO(N=2)=0.829` 是**伪读数**；
> #43 进一步核实确认该门有**结构性缺陷**（PBO 是相对量 + N 决定有无意义）。
> **性质**：**判据基础设施加固**（改 `stats.pbo_cscv` 的守卫与 docstring）。
> **不做**：不改阈值 · 不改历史判决 · 不重跑任何臂。

## §0 为什么"改判据"这件事本身要立预注册

我正在修改一道**判据门**。这比改实验更危险——若事后无据地放宽门槛，
就成了"为让结论好看而改尺子"。

⇒ 故本预注册**先把改动内容写死**，再执行。

## §1 要改什么（三项，逐条冻结）

### 改动 1 · 守卫：拒绝 N 过小的读数

| | 内容 |
|---|---|
| **现状** | `stats.py:243`：`if N < 2: return {...}` |
| **改为** | **`if N < 4: return {"pbo": None, "n_splits": 0, "n_candidates": N, "reason": f"候选策略过少（N={N} < 4）：PBO 读数无意义"}`** |
| **依据** | ω = rank/(N+1)。N=2 ⇒ ω ∈ {1/3, 2/3} ⇒ "IS 最优落中位数下"近乎必然；N=3 ⇒ 仅 3 档；**N<4 无分辨力** |
| **实测证据** | #42：N=2 ⇒ PBO 0.8286（伪）；N=16 ⇒ 0.0000（真） |

### 改动 2 · docstring 写入两条**读数前提**

在 `pbo_cscv` 的 docstring 里显式写明（#43 §5 的三条结论）：

```
⚠️ **读数前提（违反任一 ⇒ 该数字不可用于判据）**：
  ① **PBO 是相对量**：ω 是被选中策略在**候选集内**的相对秩
     ⇒ 同一策略对不同对手可算出 0.000 或 0.743（实测：对强基线 F0 = 0.743、
        对弱基线 F0day = 0.000）⇒ **报 PBO 必须同时报「对手是谁」**。
  ② **N（候选策略数）决定有无意义**：N<4 ⇒ 读数不可用（本函数已拒绝）。
     本项目**正确用法**（§44 已确立）：看对**强基线**的读数。
```

### 改动 3 · 返回值携带 `n_candidates`

| | 内容 |
|---|---|
| **现状** | 返回 `{"pbo", "n_splits", "lambda_mean", "lambda_std"}` |
| **改为** | 追加 **`n_candidates`**（= N），使调用方**无法忽略 N** |
| **兼容性** | 现有调用方 `armC14_chain.py:204` / `stability_chain.py:170` 只读 `pbo` 键 ⇒ **向后兼容**，不需改 |
