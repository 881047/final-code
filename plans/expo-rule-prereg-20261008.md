# 预注册 · 判据链 #20 · 前瞻型敞口规则（替代"权益峰值"这种内生闸门）（2026-10-08 冻结）

> §37/§39 钉死了两件事：①敞口持续性在工程上不是问题（关掉闸门就有 98.5% 在场），
> ②但常态在场会亏（MDD −64.82%、IR −0.185）⇒ 需要的是**前瞻型**的"何时该在场"规则，
> 而不是现在这种**内生**的权益峰值闸门（回撤已经发生才关，关掉之后权益冻结 ⇒ 自锁，
> 恢复纯靠运气）。本链在忠实账本上测四类规则，全部只用 t 日及以前的信息。

## 一、信号源与工程口径

`scripts/sync_index.py` 从老库 `index_daily` 取 000905/000906/000300/399001/H00906 的
OHLC+成交额 → `data/index/*.parquet`（只读老库；面板缺失 ⇒ 直接报错，不静默退回）。
所有规则参数取 250 日窗（时序标准化，与截面秩通道无关）。

## 二、臂（对象 = rank-loss 2 流集成，真 T3，daily EMA，含权口径；每臂单变量）

| 臂 | 目标敞口标量 `scale ∈ [0,1]`（乘在建仓手数上） | 依据 |
|---|---|---|
| H0 | 现行权益峰值熔断（参照，须与 #19 E0 逐位一致） | docs/03 §39 |
| **V1** | 目标波动：`min(1, σ_target / σ̂_60d)`，σ_target = 年化 12% | Moreira-Muir 波动管理（借机制，不借其做多空） |
| **V2** | 指数趋势：000905 收盘 > 其 100 日均线 ⇒ 1，否则 0.35 | 前瞻而非事后 |
| **V3** | 指数 20 日收益的时序 z 分位映射到 [0.2, 1] | 连续化，避免开关 |
| **V4** | V1 × V2（先波动后趋势，相乘即与门） | 组合 |
| V5 | V1 但 σ̂ 用**持仓已实现波动**而非指数波动 | 与自身暴露一致 |

冻结：`total_dd_halt` 在 V1–V5 一律设 0.9999（关掉内生闸门），只留
`daily_stop_loss=3%` 与 `max_cash_util=0.95`；top10/keep20/max_lots50/ATR 预算/成本
口径/数据窗全不变。H0 是唯一带熔断的臂，用作"现行"参照。

## 三、判据（含一等指标，全部同口径比）

主判据四条同时成立才算改进（vs H0）：
1. **非零敞口周占比 ≥ 70%**（常态在场，§39 的反面）；
2. **残差 IR(vs 000905) ≥ H0**（≈0.731，含权口径）；
3. **周收益 p05 ≥ H0**（−0.019）且 **MDD ≥ −30%**；
4. **β 不高于 H0 的 2 倍**（防止"靠加 β 抬收益"）。
配对：各臂 vs H0 月度对数配对 t；&#124;t&#124;≥2 记显著，但**显著而 2/3 不满足仍判负**。

仪器三件套（沿用 #19，缺一判废）：H0 逐位自证、全部臂 `blocked_cash` 占比 ≤2%、
阴性对照 = 把敞口规则喂**打乱的未来信息**（用 t+20 日的波动/趋势做 scale，
应当显著更好 ⇒ 若测不出差异，说明 scale 根本没在起作用，仪器无分辨率）。
